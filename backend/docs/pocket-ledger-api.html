账单相关接口

原数据库基准：沿用已初始化的 pocket_ledger_init.sql 四张表及字典，工资 ID=1、餐饮 ID=6；分类 ID 通过 GET /categories 获取，上方分类响应仅展示一项。无需新建业务库或改表，也不要重跑含 DROP TABLE 的初始化脚本。细分的 user_id 由服务端写入；删除账单、注销用户由应用事务显式清理关联数据，数据库没有外键级联。

账单参考实现补充约束：ID 必须为正整数，JSON 浮点 ID、额外请求体字段返回422。金额对应 DECIMAL(12,2)，整数最多10位、小数最多2位，输出为两位小数字符串。账单日期范围为1000-01-01至Asia/Taipei当天。描述与细分名称先trim，再按Java UTF-16长度校验；PUT中description缺失/null均清空。相同日期再按id同方向排序。数据库死锁或锁争用返回HTTP/code 409“数据正在被修改，请稍后重试”。这些规则与开发书中的参考代码配套，实施后需一同验收。

认证：本组全部接口都需要 Authorization: Bearer <JWT>。服务端只操作当前用户的数据，请求体不接受 user_id。

POST 新增账单 需要认证

基本信息

Path： /bills/add

Method： POST

接口描述：新增一笔收入或支出账单，可同时提交最多 20 个显式细分项。

请求参数

Headers

参数名称参数值是否必须备注
AuthorizationBearer <JWT>是登录令牌
Content-Typeapplication/json是请求体格式

Body

名称类型是否必须默认值备注其他信息
category_idinteger必须—分类 ID分类必须存在
amountdecimal必须—账单总金额> 0；最多 12 位、2 位小数
descriptionstring | null否null账单说明去除首尾空白；最长 200 字符
bill_datedate必须—账单日期YYYY-MM-DD；不得晚于今天
breakdownsobject[] | null否null显式细分项最多 20 项；null / [] 表示不启用细分
├─ item_namestring必须—细分名称1–50 字符；不可使用保留名“其他”
└─ amountdecimal必须—细分金额> 0；最多 12 位、2 位小数
 
{
  "category_id": 6,
  "amount": "68.50",
  "description": "晚餐",
  "bill_date": "2026-09-04",
  "breakdowns": [
    { "item_name": "主餐", "amount": "50.00" },
    { "item_name": "饮料", "amount": "12.00" }
  ]
}

返回数据

返回 BillResponse 账单对象；新增响应会加载细分项。

{
  "code": 200,
  "message": "添加成功",
  "data": {
    "id": 101,
    "category_id": 6,
    "category_name": "餐饮",
    "type": "expense",
    "amount": "68.50",
    "description": "晚餐",
    "bill_date": "2026-09-04",
    "breakdowns": [
      { "id": 201, "item_name": "主餐", "amount": "50.00", "sort_order": 0, "source": "user" },
      { "id": 202, "item_name": "饮料", "amount": "12.00", "sort_order": 1, "source": "user" },
      { "id": null, "item_name": "其他", "amount": "6.50", "sort_order": 2, "source": "system" }
    ]
  }
}

显式细分合计小于账单总额时，服务端会在响应中追加不入库的“其他”余项：id=null、source=system。

错误响应

HTTP / codemessage触发条件
400分类不存在category_id 无对应分类
400细分金额不能超过账单总额细分金额合计大于 amount
401未登录或登录已失效认证失败
422参数错误：…日期、金额、字段或细分项不符合约束

通用错误

除根路径健康检查外，框架错误与业务错误也使用统一 Result 结构，且 HTTP 状态码与响应中的 code 相同。

HTTP / code含义典型 message
400业务参数不合法分类不存在；细分金额不能超过账单总额
401认证失败未登录或登录已失效；用户名或密码错误
404资源或路径不存在账单不存在；Not Found
405请求方法不允许Method Not Allowed
409资源冲突用户名已被占用
422请求参数校验失败参数错误：字段名 校验原因
500未处理的服务端异常服务器内部错误
